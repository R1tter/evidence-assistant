# HTTP API and optional AI generation

Build with `npm run build`, then run `npm run start:api` from the repository root. The server binds to `127.0.0.1:3001` by default; `PORT` overrides the port. Corpus files resolve relative to the server module, not the working directory. Startup loads the original documents and builds one immutable retrieval index.

## Endpoints

- `POST /api/ask`: `{ "question": "How should tests be selected?", "mode": "demo" }`. The question is trimmed and limited to 1–1,000 Unicode code points; modes are `demo` and `llm`. Extra request fields are rejected. Requests have a 16 KiB body limit.
- `GET /api/config`: only `{ "llmAvailable": boolean }`.
- `GET /api/documents`: public ID, title and corpus-relative path.
- `GET /api/documents/:id`: the original public document. ID lookup never resolves a client-supplied filesystem path.

The demo returns extractive answers and requires no credentials. AI mode is optional: set `OPENAI_API_KEY` and `OPENAI_MODEL` in the server environment. `.env.example` contains empty examples; the server does not automatically load `.env` files. A key without an explicit model fails startup safely. Choose a model supporting Responses structured output. No model or paid usage is selected automatically.

The OpenAI adapter uses [Responses structured output](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), an 800-token output cap, a 20-second SDK timeout, zero automatic retries and `store: false`. Instructions are separate from JSON-encoded question/evidence. The core validates returned structure, retrieved source IDs and exact quotes; semantic correctness and prompt-injection resistance are not guaranteed. Unsupported queries abstain without calling an available provider. Request mode is owned by the API, not provider output.

## Capacity, errors and cancellation

The single API process runs at most two provider calls and queues eight. Queue waiting counts toward the 20-second provider deadline. Overflow returns 429 with `Retry-After: 1`; disabled AI returns 503, invalid output/refusal/upstream failure 502, and deadline expiry 504. Aborted work is removed from the queue, propagated to the provider and releases local capacity. Adapters must honor the abort signal; this does not guarantee that a remote provider stops computation or billing. These controls are not distributed quotas.

Errors have `{ "error": { "code": "PROVIDER_TIMEOUT", "message": "...", "requestId": "..." } }`. Messages omit upstream details and secrets. Request IDs are generated by the server. Logs contain only request ID, recognized mode, status and duration. Framework request logging is disabled; no prompts, documents, answers or credentials are logged.

Baseline verification uses Fastify injection, a real HTTP disconnect and the official SDK with mocked external HTTP responses. No live OpenAI call has been executed; account/model compatibility and real output quality remain unverified. The compiled startup and credential-free demo were smoke-tested locally.
